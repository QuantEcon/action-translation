### Fixed

- **`translate init` fails a lecture whose state file it cannot write, and `translate forward` reports the same failure for a file it writes locally** (#378). Both caught every error from the state write and carried on, so the lecture was counted as translated and the run passed with no state file beside it. Under `sync-scope: existing` a lecture without one is out of scope, so it never synced, and the docs told the operator to check that each state file existed before committing. `init` now writes the state file before it counts the lecture: if the write fails, the lecture fails with the new `state-write` kind in `--report-json`, the translation stays on disk, its tokens still count, and the run exits 1. After the failure lines, the run prints, for each such lecture, the `translate status --write-state` command that records it once the cause is fixed, with the edition's own `-s`, `-t`, `-l` and `-d`: `status` reads no config, and a bare `status -f <file> --write-state` resets an `fa` edition's config to `zh-cn`. The warning `--skip-existing` gives for a lecture with no state file now names the same full command. A state folder `init` cannot write at all stops the run before any model call, instead of failing each lecture after its translation is paid for. `forward` logs a failed write as an error and exits 1, and computing the state no longer sits in a `catch` that could have left the state file out of a `--github` PR. When the source clone has no commit for the lecture, both now warn that its state file records `source-sha: unknown`, which `translate status` reports `OUTDATED` once the lecture is committed. The manual check is gone from the CLI reference, the FAQ and both tutorials.
- **`translate status --write-state` says what it wrote, and exits 1 when it wrote no state file or failed to write one** (#401). It printed `.translate/ metadata written to <target>` whatever happened: a mistyped `-f`, a lecture only one repository has, and a write that failed all printed the banner and exited 0, and the config was written even when no state file was. The banner now counts the state files written and says whether the config was, and each file left without one is listed with the reason: `source only`, `target only`, `not found`, or the write's error. A run that wrote no state file, or failed to write one, exits 1, and one that can write none leaves `.translate/config.yml` as it was. `--json` output carries the same record as `writeState`.
