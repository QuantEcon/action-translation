### Fixed

- **A removal the edition cannot read fails the run, instead of passing with the lecture still in the edition** (#396). Sync and rebase took any failed read of a removed lecture as "already gone": a rate limit or a 5xx skipped the deletion, and the run passed. Only a 404 now means the edition no longer has the file. Any other status is a fetch error: sync fails the run and opens a failure issue, while the PR's other files still sync, and rebase stops before the branch moves. GitHub also answers 404 for a repository the token cannot see, so sync trusts a removal's 404 only after it reads the edition repository itself, as the scope check does: a removal-only PR against a misspelt `target-repo` used to pass with nothing done. A removed lecture whose state file read fails, or a renamed lecture whose state file at its old path read fails, is held back with an error, since whether to delete that file is unknown. A renamed lecture whose old state file the premise check reads keeps that check's error. A removed lecture the edition no longer has, whose state file is still there, now has that state file deleted, listed under Files Deleted in the sync PR, and in rebase, in the rebased commit; the success comment counts the lecture among the files synced. A removal that leaves nothing to delete is not declared in the PR's metadata.
- **A bibliography that cannot be read fails the sync with a failure issue** (#386). When the edition's `_config.yml`, or a file its `bibtex_bibfiles` lists, could not be read, in the edition or in the source, the error ended the run outside every check, so the run failed with no failure issue, and none of its other errors reached one either. The whole sync is now held: no lecture, ToC or removal goes ahead, the model is not called, and the failure issue lists every error the run recorded, the bibliography's last. Its Recovery section says the run synced nothing, to make the file the error names readable (a transient error needs nothing), and to sync the PR again with `\translate-resync` under its usual condition, or lecture by lecture with the CLI. It gives no recovery line per lecture, since no lecture failed. Rebase mode already stopped before the branch moved.
