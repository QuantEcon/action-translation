### Documentation

- **The setup tutorials match the CLI** (#383). `connect-existing.md` no longer shows `forward --dry-run`, which `forward` rejects, and acts on `CONTENT_CHANGES`, the verdict `status --check-sync` prints, instead of `CONTENT_STALE`; its two cross-references to the heading-map and verification steps point at Steps 5 and 7. `fresh-setup.md` lists the files `translate setup` writes (the review and rebase workflows, not `translation-sync.yml`), says the source repo's sync workflow is written only with `--source-workflow`, and puts heading-maps inside the translate phase of `init`'s phase table. `fresh-setup.md` and `add-language.md` no longer ask the reader to create the review workflow `setup` already committed.
- **Removing an orphaned translation removes its state file, and a renamed lecture has a recipe** (#399, the documentation half). `resync-drifted.md` now `git rm`s `.translate/state/<file>.yml` with the lecture and the `_toc.yml` entry, and moves the translation and its state file when the source renamed the lecture. The weekly status workflow in `automated-maintenance.md` prints "All N files are aligned" only when every file is `ALIGNED`, and otherwise gives the counts. `translate status` and `translate doctor` still do not tell an orphan from an edition-only file (#399).
