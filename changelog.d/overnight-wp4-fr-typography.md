### Fixed

- **French typography no longer writes non-breaking spaces into CSS, table delimiter rows or cell-break metadata** (#325). The `fr` typography pass treated three kinds of line as prose. In a raw `<style>` block it wrote `width : 70% ;` with U+00A0, which is not CSS whitespace, so the browser dropped the declarations (the fr edition's `getting_started` figures render full-width). In a table delimiter row it wrote `| :- : |`, which no longer parses as one, so the table renders as a paragraph of pipes (the fr edition's `pandas.md`). In a `+++ {"user_expressions": []}` cell break it made the JSON unparsable. The pass now leaves raw `<style>`, `<script>`, `<pre>` and `<textarea>` blocks alone (multi-line or on one line, also inside a note), and `+++` lines and delimiter rows too, and still typesets the prose around them. A delimiter row an earlier version damaged is repaired, so the fr `pandas.md` table heals on the next sync of that file. A damaged `<style>` block is not repaired: **after this release reaches `@v0`**, the fr edition needs its one-off PR removing the U+00A0 from `getting_started.md`'s `<style>` block (and, if the sync has not already healed it, from `pandas.md`'s delimiter row). Before that release, a hand repair would be re-damaged by the next sync.
- **A French elision apostrophe before inline markup no longer renders as a closing quote** (#324). In `de l'[Exercice 1](x)`, `d'*arguments*`, ``d'{ref}`appels` `` or `d'« apprendre »`, docutils smartquotes cannot tell that the straight `'` is an elision, and for French renders it as ”: "de l”Exercice 1" (24 places on 13 pages of the fr edition). The `fr` typography pass now writes U+2019 there, for a closed list of elision prefixes at a word start, and leaves in-word apostrophes (`aujourd'hui`) and everything outside prose alone. Heading matching treats `’` and `'` as the same character, so a heading that gains the curly apostrophe still matches its recorded heading-map entry. `scripts/typography/apply.mjs` accepts the change and reports the count beside the non-breaking spaces. **Before this release reaches `@v0`**, heal the fr edition with the patched `scripts/typography/apply.mjs` in one fr PR. Otherwise the first sync of each affected fr file carries apostrophe changes in sections its English change did not touch.
