### Fixed

- **Rebase mode stops, instead of translating a lecture again, when a PR merged since added a lecture this PR adds too** (#467). Two translation PRs can add the same lecture: the sync of a source PR and a `\translate-resync` of it, or the syncs of two source PRs that both touch a lecture new to the edition. Once one merged, rebase mode rebuilt the other as an update of `main`'s copy; the rebase cache and the previous English were both missing for a new lecture, so every section was translated again at full cost and the branch's reviewed translation was dropped. When `main` has a lecture, rebase now also reads it at the PR's baseline and, if the baseline lacks it, on the PR's branch. A lecture `main` has, the baseline lacks and the branch has stops the rebase of that PR before anything is translated or pushed, with the branch as it was, and the failure comment names the lecture and asks a person to decide which copy wins. Any failed read there other than a 404 fails the rebase of that PR too. An ordinary update makes the same reads as before (the rebase cache reuses the new baseline read); a lecture the PR never delivered that `main` has, and a renamed lecture `main` still has under its old path, each cost one read more.
- **A lecture's state file keeps the keys the engine does not own** (#290). Every writer rebuilt `.translate/state/<file>.yml` from its six fields, so any other key, such as the editor sign-off block (`reviewed:`) an edition-side workflow is to record, was erased by the next sync, `init`, `forward` (on disk and with `--github`), `status --write-state` or rebase. Each writer now reads the existing file and keeps every top-level key it does not own, with its value, after the engine's keys, which keep their order and formatting: a state file with no other key is written byte for byte as before, so sync PRs carry no new state-file churn. A renamed lecture's state file moves with its other keys unless the new path already has one; a removed lecture's state file is still deleted. Limits: YAML comments in a state file are not kept, and a kept value may be re-quoted, as with `config.yml`; an existing state file that is not a YAML mapping is overwritten with a warning naming it (`status --write-state` still refuses one without `--force`). The sync Action and rebase mode reuse the state-file reads they already made, so they make no extra read; a lecture whose own state file the edition answers with anything but a 404 is now held back (sync: in the failure issue; rebase: the PR's rebase fails with the branch untouched) instead of being written over. Before release, exercise this on the `test-translation-sync` lanes with a state file carrying an extra key, as #290 asks; it was not run here, since the harness makes billed model calls.
- **A review finding that quotes another lecture of the PR is filed under that lecture** (#223). The reviewer sometimes names one file while its description quotes another file of the same PR (lecture-python.zh-cn#208: an accuracy finding on `kesten_processes.md`'s Gibrat section quoting `olg_adaptive_money.md`), so an editor sent there found nothing to act on. On a PR that reviews more than one file, review mode now checks each reviewer finding's quoted text (in backticks or quotation marks, 6 characters or more) against every reviewed file's English and translation, before and after the PR, with whitespace, non-breaking spaces, apostrophes and case folded. Only when no quote is in the named file and the quotes found are all in one other file is the finding moved there, with its location cleared; otherwise, as when a quote is common to several lectures, it is left as the reviewer wrote it. Severity, category and text never change, no finding is dropped, and routing is unchanged; each move is logged in the run. The verdict schema is unchanged, but verdict records may now attribute such a finding to a different file than before, which matters for per-file shadow data across this release. A finding whose quotes match no file, or several, keeps its file and location as before.
