### Fixed

- **A CLI analysis call whose response is cut off mid-read is retried, instead of failing the file.** v0.30.2 retried a connection dropped while a response streams (#436). The three CLI analysis calls, `forward`'s triage, `backward`'s document comparison and its section evaluation, are not streamed: there the same drop makes `messages.create()` reject with fetch's bare `TypeError('terminated')`, which the SDK passes through unwrapped because it reads the body after the request has resolved, so the retry predicate let it through and one dropped connection failed the file. `isRetryableAnthropicError` now also retries exactly that error (`isBodyCutShort`), by name and message, with the same three attempts and backoff; any other `TypeError` is still not retried. Both checks now match the error by name rather than `instanceof`, since fetch's errors come from Node's own undici, which under Jest is another realm. `init --report-json` counts one that outlasts the retries as `infra`, as it does the streamed form, though `init`'s own calls are streamed, so the rate check sees no change.
