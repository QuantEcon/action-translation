### Fixed

- **A failed read of one source file now fails the review run instead of silently narrowing it** (#261). Review mode read each file's English source with any error taken as "the file is absent", so a rate limit or a 5xx on one file of a multi-file PR dropped that file from the review, and the PR could PASS and record `auto-merge` (or `wouldAutoMerge: true` in shadow mode) having reviewed less than the PR. Only a 404 now means a source file is absent; any other failure on a source read fails the run before any model call, with an error naming the file, so a rerun reviews the whole PR. This holds for sync PRs and for CLI resync PRs. A reviewed file whose source is genuinely absent (a 404) while the others were compared routes the PR to `editor`, with the file named in the recommendation reasons and the comment. A failure to read the source PR itself is unchanged: the review fails as having no source content.
- **A diff evaluation that never parses no longer kills the review** (#284). About 2% of the time the diff evaluation's reply is not valid JSON on all three attempts, and the review run failed with no verdict posted, discarding the translation evaluation it had already paid for. The three attempts stay. When all three fail to parse, the review now posts its verdict with `scopeCorrect` and `positionCorrect` recorded as `false`, gating through `diff-check` findings that carry the fixed phrase `diff evaluation returned no parseable verdict`, so the PR routes to `editor`. The run ends green with a warning, the deterministic diff checks run and report as usual, and the failed attempts count in the token usage. In calibration data, a `diff-check` finding with that phrase means the model gave no answer, not that it judged the check failed. An API error, a refusal or a truncated reply in the diff evaluation still fails the run, and so does a translation evaluation that never parses.
- **Review mode no longer reports an unchanged section as changed when two headings share their text** (#283). Review matched a PR's sections before and after by heading text alone, dropping the level, so `### Applications in Economics` and `#### Applications in Economics`, or a heading repeated in one lecture (`## Exercises` twice), collided: an unchanged section was reported as modified on every PR touching the lecture, and a deleted duplicate could go unreported. Such headings are now matched by level and text, the nth to the nth. **The "Changed Sections" list given to the reviewer changes on lectures with such headings** (about 7% of English lectures, per the issue): it drops the spurious entries and gains the missed ones. The reviewer's prompt text is unchanged, but shadow-mode data from such lectures shifts slightly from this release. Lectures whose headings are all distinct get exactly the same list as before. The harness evaluator's copy of the function (`tool-test-action-on-github/evaluate`) is fixed in step.
