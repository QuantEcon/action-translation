### Fixed

- **A failed read of one source file now fails the review run instead of silently narrowing it** (#261). Review mode read each file's English source with any error taken as "the file is absent", so a rate limit or a 5xx on one file of a multi-file PR dropped that file from the review, and the PR could PASS and record `auto-merge` (or `wouldAutoMerge: true` in shadow mode) having reviewed less than the PR. Only a 404 now means a source file is absent; any other failure on a source read fails the run before any model call, with an error naming the file, so a rerun reviews the whole PR. This holds for sync PRs and for CLI resync PRs. A reviewed file whose source is genuinely absent (a 404) while the others were compared routes the PR to `editor`, with the file named in the recommendation reasons and the comment. A failure to read the source PR itself is unchanged: the review fails as having no source content.
