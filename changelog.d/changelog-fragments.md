### Changed

- **Changelog entries go in fragments, one file per pull request, collected at release.** Every PR added its entry at the top of `CHANGELOG.md`'s `[Unreleased]` section, so each merge conflicted every other open PR: the ten PRs of 2026-11-15 and 16 took 15 rebases between them. A PR now adds `changelog.d/<branch without its prefix>.md`, with its sections and entries written as they will appear (format in `changelog.d/README.md`). The release PR runs `npm run changelog -- --release X.Y.Z`, which writes them under the version's header, deletes them, and prints the sections as the draft release notes. `npm run changelog:check` runs in CI. It validates the fragments, and fails a PR that adds an entry to `[Unreleased]` directly, which now stays empty between releases. The entries already under `[Unreleased]` moved into fragments unchanged. This is a first version: nothing yet requires a PR to carry a fragment.
