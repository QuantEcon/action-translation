### Fixed

- **A lecture moved out of `docs-folder` is deleted from the edition, with its state file** (#398). GitHub lists such a move as a rename under the new path. Sync decided what a rename was from the new path alone, so the entry matched no list and was dropped: the edition kept the translation and its state file, and a ToC edit in the same PR left the lecture outside the edition's toctree, with nothing in the log, the PR or the review naming it. The other half of #307, which fixed the old path, now covers this. A docs-folder lecture renamed to a path outside the folder is a removal of its old path, so the sync PR deletes the translation and its state file and lists both under Files Deleted, and the log says why. Review counts the deletion as one the source PR made, so the PR gets the deletion-only review instead of an aborted run (#210). A lecture renamed to a name that is not `.md` inside the folder, such as a conversion to `.ipynb`, is left in the edition, since the source's ToC still lists it, and the run warns that sync no longer updates it. When the docs folder's own `_toc.yml` is moved out of it, or removed while a `_toc.yml` outside the folder is added (GitHub's listing of a ToC moved and rewritten), the source has moved its book, and taking each lecture's move as a removal would delete every translation. The run is refused instead, with a failure issue. It says to move the edition's files the same way in a PR of its own, and to point the workflow's `docs-folder` and `paths:` at the new folder. It also says not to resync the PR. Whether a workflow's `paths:` filter fires on a rename's old path alone is unverified; a move usually comes with a ToC edit, which it does match.
