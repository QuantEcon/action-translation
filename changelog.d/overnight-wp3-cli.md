### Added

- **`init` and `forward` keep what the parity guard refused, in `.translate/refused/`** (#364, #430). When the structural parity guard refused a translation, the model's output was discarded, so a refusal could be read only through the guard's message, which describes the symptom (a whole-document code fence reads as a renamed directive). The bytes the guard checked are now written to `<target>/.translate/refused/<lecture>`, the lecture's path under the docs folder, and the lecture still fails. The failure names the file (`TRANSLATION-REPORT.md`'s Failures entry, `init -f`'s stderr, `forward`'s log and bulk summary, and `refusedOutput` in `--report-json`), and the console and the Failures entry show the output's first and last three lines: the first three after the front matter `init` and `forward` add, so a code fence that opens the reply shows first, each line with control characters shown as `�` and cut at 200 characters. The folder carries a `.gitignore` of `*`, checked before every write and replaced when it has no `*` line, so it is never committed, in existing editions too, and `setup` adds `.translate/refused/` to the `.gitignore` it writes; `status`, `doctor --require-state` and sync do not see it. A later translation of the lecture removes its refused output. Nothing is written through a symbolic link, the folder's `.gitignore` included, and no lecture named `.gitignore` is kept: the failure then says why the output was not kept. With `docs-folder: .` the folder is inside the docs folder, so a local `jupyter-book build` would read it; the CLI reference says how to exclude it. `--report-json` now keeps a parity failure's message whole, every violation listed, where it cut every message at 500 characters; other failures are still cut. Since `rate-check.sh` uses each draw's directory as `init`'s target, a refused draw's output is kept in the run directory with no change to the script.

### Fixed

- **`translate status` and `backward` no longer read a lecture synced from a merge-commit or rebase merge as changed** (#391). Sync records the source PR's merge commit as `source-sha`, which after a merge commit, or a rebase merge whose last commit did not touch the lecture, is not the lecture's last commit. `status` compared the two commits, so it reported the freshly synced lecture `OUTDATED` (and bulk `forward` resynced it), and `backward` analysed it instead of skipping it. When the commits differ, both now compare the English file's content at the recorded commit with its content now, and an unchanged file reads as in sync. A recorded commit that is not in the local source clone, or an id that names something other than a commit (such as a tree), still reads as changed. Sync still records the merge commit; recording the commit that last touched each lecture, the issue's second part, remains open.
- **`translate init --resume-from` refuses a name it cannot resolve, instead of translating the whole series** (#384). It took the first ToC entry that contained the name, and a name that matched nothing printed one line and started again from the first lecture, paying for every lecture already translated. It now names the lecture as `-f` does (the path, else a unique file name, else a unique part of the path) and stops before any translation or write when the name matches no lecture or more than one, naming them. An empty name (`--resume-from "$NEXT"` with `NEXT` unset, or `-f ""`) is refused the same way rather than read as no name. `--dry-run` with `--resume-from` now lists only the lectures the run would translate. `--resume-from` with `-f` is refused at the start, since it applies to a bulk run.
- **A whole-document translation that ends with the incomplete-document marker is no longer reported as truncated** (#428). When the model stopped and printed the marker, `init`, `forward` and sync said "Document exceeded token limits and was truncated" and advised section-by-section translation, though a response that reaches its output limit is refused earlier as truncated and never reaches that check. The message now reads "The model stopped and printed the incomplete-document marker after N output tokens, short of its limit of M: the response was not truncated." The run report's `incomplete` class now matches that message through one shared constant, and `rate-check-summary.mjs` accepts both wordings, so a control run at an older tag still scores the old one. The prompt still offers the model the marker; whether to remove it, the issue's third point, changes what each request sends and needs a billed check, so it remains open.
- **`init` and `forward` count the tokens of every response, the failed files' included** (#356). `init`'s console summary and `TRANSLATION-REPORT.md` printed `Tokens:` / `Total Tokens Used:` as the sum of the successful lectures' final responses, so a lecture the parity guard refused, though paid for, counted 0; `forward` counted only a successful resync and never its triage. Both now print one line from the translator's own count, in the shape the Action logs: `API usage: <calls> call(s), <input> input + <output> output tokens, cache: <read> read + <written> written`. `init` prints it in its summary and writes it to `TRANSLATION-REPORT.md` as `API Usage`; `forward` prints it per file with `-f` and in the bulk summary, counting triage and resync on every path, a refused triage included, and with `-f` also when the file then fails with an error. `--report-json` already counted every response and is unchanged. `runInit`'s returned stats carry `usage` in place of `totalTokens`.
