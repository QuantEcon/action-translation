### Fixed

- **`translate status` and `backward` no longer read a lecture synced from a merge-commit or rebase merge as changed** (#391). Sync records the source PR's merge commit as `source-sha`, which after a merge commit, or a rebase merge whose last commit did not touch the lecture, is not the lecture's last commit. `status` compared the two commits, so it reported the freshly synced lecture `OUTDATED` (and bulk `forward` resynced it), and `backward` analysed it instead of skipping it. When the commits differ, both now compare the English file's content at the recorded commit with its content now, and an unchanged file reads as in sync. A recorded commit that is not in the local source clone still reads as changed. Sync still records the merge commit; recording the commit that last touched each lecture, the issue's second part, remains open.
- **`translate init --resume-from` refuses a name it cannot resolve, instead of translating the whole series** (#384). It took the first ToC entry that contained the name, and a name that matched nothing printed one line and started again from the first lecture, paying for every lecture already translated. It now names the lecture as `-f` does (the path, else a unique file name, else a unique part of the path) and stops before any translation or write when the name matches no lecture or more than one, naming them. `--dry-run` with `--resume-from` now lists only the lectures the run would translate.
- **A whole-document translation that ends with the incomplete-document marker is no longer reported as truncated** (#428). When the model stopped and printed the marker, `init`, `forward` and sync said "Document exceeded token limits and was truncated" and advised section-by-section translation, though a response that reaches its output limit is refused earlier as truncated and never reaches that check. The message now reads "The model stopped and printed the incomplete-document marker after N output tokens, short of its limit of M: the response was not truncated." The run report's `incomplete` class now matches that message through one shared constant, and `rate-check-summary.mjs` accepts both wordings, so a control run at an older tag still scores the old one. The prompt still offers the model the marker; whether to remove it, the issue's third point, changes what each request sends and needs a billed check, so it remains open.
- **`init` and `forward` count the tokens of every response, the failed files' included** (#356). `init`'s console summary and `TRANSLATION-REPORT.md` printed `Tokens:` / `Total Tokens Used:` as the sum of the successful lectures' final responses, so a lecture the parity guard refused, though paid for, counted 0; `forward` counted only a successful resync and never its triage. Both now print one line from the translator's own count, in the shape the Action logs: `API usage: <calls> call(s), <input> input + <output> output tokens, cache: <read> read + <written> written`. `init` prints it in its summary and writes it to `TRANSLATION-REPORT.md` as `API Usage`; `forward` prints it per file with `-f` and in the bulk summary, counting triage and resync on every path, a refused triage included. `--report-json` already counted every response and is unchanged. `runInit`'s returned stats carry `usage` in place of `totalTokens`.
