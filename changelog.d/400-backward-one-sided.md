### Fixed

- **Bulk `translate backward` analyses only the files both repositories have, so a lecture on one side no longer fails the run** (#400). It analysed the union of the two lecture lists, so each file on one side only threw before any model call and counted as an error: a lecture the edition has not translated yet (`TARGET file not found`), an edition-only page, which the FAQ documents as the way to add content to an edition, and a translation whose English was removed (`SOURCE file not found`). Since #160 a run with an errored file exits 1 and `--resume` retries it, so on such an edition every run and every resume failed until each file was listed in `--exclude`; the CLI reference's own example, lecture-python-intro against lecture-intro.zh-cn, failed on five. Bulk mode now analyses the intersection and lists the rest as skipped, with the side each is on, on the console (`Skipped 3 file(s) present on one side only: ...`), in `_summary.md`, and as `oneSidedFiles` in `_summary.json`, an optional field, so the schema version is unchanged. A run left with nothing to analyse says why (`No files to analyze: 3 unchanged since last sync, 2 on one side only.`), keeping the path hint for a run whose discovery found nothing, and a fresh run of that kind now writes its summary too. Since a mistyped `--target` would otherwise make every file one-sided and pass, a run in which one repository's docs folder has no `.md` files at its top level while the other's has some stops with exit 1 before writing anything, naming the folder. `-f` still fails on a file either repository lacks.
