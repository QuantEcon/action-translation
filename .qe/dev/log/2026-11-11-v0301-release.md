- **Scenario 09, zh-cn and ml**: both sync runs failed inside 40 seconds with `Translation
  failed for modified section: terminated`. That is a connection dropped while a response was
  streaming. The engine does not retry it: `isRetryableAnthropicError` takes rate limits,
  connection errors and 5xx, and a stream cut mid-read reaches it as a plain SDK error. The
  rate check's classifier already counts the same error as infra. Not new in v0.30.1: section
  calls streamed at v0.30.0 under the same retry rule. Scenario 09 changes nearly every section,
  so it makes the most streamed calls of any scenario.
- **Scenario 07, ml**: the sync PR was delivered and no review comment appeared in 17 minutes.
  The review run's log was not read before the next run reset the repository.

Scoped reruns at the same tag, `--scenarios 09` and then `--scenarios 07`, each delivered a sync
PR and a PASS review on all three lanes. Combined: 28 of 28 delivered and reviewed per lane.
The tally is on #434.

A first hypothesis here was wrong and is recorded so it is not picked up again: that #419's
64,000-token section cap was drawing 429s by reserving output-token rate limit up front. The
error text settled it; no 429 was involved.

## How the tally was read

The test repositories are public, and GitHub search covers them: open PRs per lane, comment
counts, and comment text. Verdict words are inferred from phrase search over the review
comments (`verdict PASS`), and the count of comments carrying `engineVersion 0.30.1` is exact.
Run status and logs are not reachable that way, so a missing PR cannot be told from a run still
in flight without the Actions page. Comment search lags a new comment by one to two minutes.

A scoped harness run resets all four repositories, so a full run's results have to be captured
before any rerun.
